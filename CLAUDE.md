# Proyek: point.lat

Media edukasi praktis berbahasa Indonesia. Spesifikasi: `docs/superpowers/specs/2026-11-03-point-lat-design.md`. Rencana: `docs/superpowers/plans/`.

## Tech stack
- Next.js 16 (App Router) + Payload CMS 3.92 dalam satu aplikasi
- PostgreSQL dengan `@payloadcms/db-postgres`, tanpa Docker (keputusan pemilik 2026-11-09: hanya Next.js, Vercel, dan Supabase). Produksi dan pratinjau di Supabase (Singapura) lewat pooler Supavisor mode transaksi, skema hanya lewat migrasi Payload. Komputer pemilik memakai proyek Supabase pratinjau untuk `npm run dev` (juga lewat migrasi). Tes otomatis (CI dan sesi Claude) memakai Postgres di mesin itu sendiri dengan push skema: bawaan runner GitHub di CI, paket sistem di sesi Claude
- Hosting Vercel Hobby (keputusan pemilik 2026-11-07): cron hanya sekali sehari (`0 23 * * *`, sekitar 06.00 WIB, bisa meleset sampai 59 menit), satu aturan rate limit Firewall, dan hanya untuk penggunaan non-komersial, jadi pindah ke Pro sebelum iklan dinyalakan (fungsi di `sin1`; ditegaskan lagi 2026-11-09: "Vercel free"). Jadwal 10 menit bisa didapat tanpa Pro lewat Supabase Cron (`pg_cron` + `pg_net` memanggil `/api/jobs/run`, runbook rilis H5, opsional). CI dan backup mingguan di GitHub Actions (repo `vanhallen28/point.lat`)
- Editor Lexical (`@payloadcms/richtext-lexical`)
- Vitest (unit + integrasi), Playwright + axe (e2e)
- Frontend: CSS Module + token CSS (`src/styles/tokens.css`), font Archivo variable lewat `next/font/local`. Logo (sejak v1.1.0): SVG inline di `src/components/dasar/Logo.tsx`, digambar ulang dari file logo pemilik ("POINT.", huruf O berupa tanda cincin dan panah naik, titik biru); favicon `src/app/(frontend)/icon.svg` dari tanda yang sama. Biru `--merek-biru` (#2F6BFF) hanya untuk logo dan grafik merek, tidak untuk teks
- Node 26 (`engines` `26.x`: Vercel memakai 26.x terbaru, CI 26.13.0, `.nvmrc` untuk nvm), npm 11.20.0 bawaan Node 26.13.0 (`package-lock.json`; skrip instalasi dependensi hanya yang tercatat di `allowScripts` `package.json`, sekarang esbuild). Di Node 26 `fetch` bawaan memakai HTTP/2 bila server mendukung (Undici 8); tes memakai adapter palsu, jadi perilaku HTTP/2 ke Google, IndexNow, dan Claude baru teruji di uji langsung runbook rilis

## Perintah
- Database: tanpa Docker. Komputer pemilik: `DATABASE_URL` dan `DATABASE_CA` di `.env` menunjuk proyek Supabase pratinjau, lalu `npm run migrate` dan `npm run seed` sekali. Sesi Claude: Postgres sistem (`pg_ctlcluster 16 main start`, user dan password `postgres` di `127.0.0.1:5432`, database `pointlat_test` dibuat sekali). CI: `scripts/ci-postgres.sh` menyalakan Postgres bawaan runner
- Dev: `npm run dev` (admin di http://localhost:3000/admin)
- Tes unit: `npm run test:unit`
- Tes integrasi (butuh Postgres lokal dari `.env.test`, bukan Supabase): `npm run test:int`
- Semua tes: `npm test`
- Tes E2E (butuh Postgres lokal, membangun build produksi dulu): `npm run test:e2e`. Database E2E = nama database tes ditambah `_e2e`, dibuat dan diisi ulang otomatis oleh `tests/e2e/siapkan.ts`.
- Type check: `npm run typecheck`
- Tipe Payload: `npm run generate:types` (jalankan setiap kali field berubah)
- Import map admin: `npm run generate:importmap` (jalankan setiap kali menambah fitur Lexical atau komponen admin)
- Data awal: `npm run seed` (pilar, penulis, halaman draf, global, dan enam kalkulator draf beserta parameternya; dokumen yang sudah ada tidak ditimpa)
- Aset sistem Cloudinary (sekali per akun, butuh kredensial): `npm run media:siapkan`
- Pekerjaan cron sekali jalan tanpa Vercel (jadwal terbit, antrean Mesin Indexing, dan tugas Pantau SEO yang jatuh tempo): `npm run indexer`
- Migrasi Payload ke database di `DATABASE_URL`: `npm run migrate`. Migrasi baru setelah skema berubah: `npm run payload -- migrate:create <nama>` (lihat Konvensi, database dan migrasi)
- Build Vercel (`buildCommand` di `vercel.json`): `npm run build:vercel`, yaitu `npm run periksa:rilis` (env dan penanda database), `npm run migrate`, `npm run periksa:rilis` lagi (database baru ditandai), lalu `npm run build`
- Lighthouse CI (setelah build E2E, port 3100 kosong, `CHROME_PATH` ke Chromium Playwright, env server seperti langkah Lighthouse di `ci.yml`): `npm run lighthouse`
- Cadangan dan pemulihan database: `scripts/cadangkan-database.sh` dan `scripts/pulihkan-database.sh` (runbook `docs/operasional/pemulihan-database.md`)
- Rilis dan uji langsung (langkah pemilik dari nol sampai live, lalu uji layanan luar): runbook `docs/operasional/rilis.md`

## Konvensi
- Nama domain memakai bahasa Indonesia, sama dengan spesifikasi: slug koleksi (`artikel`, `pilar`), nama field (`judul`, `intinya`), nama fungsi modul (`kabari`, `hitung`, `pathFor` adalah pengecualian yang sudah ada).
- Nama teknis framework tetap bahasa Inggris (hook, access, config).
- Logika bisnis ditulis sebagai fungsi murni di `src/lib/` atau `src/modules/` dan diuji unit. Config Payload hanya merangkai.
- Satu file satu tanggung jawab. Koleksi di `src/collections/`, global di `src/globals/`, blok di `src/blocks/`, field bersama di `src/fields/`, hook di `src/hooks/`, akses di `src/access/`.
- Path publik selalu dibangun lewat `pathFor()` di `src/lib/paths.ts`, jangan merangkai string URL manual. Halaman indeks memakai `PATH_INDEKS` (`/cari`, `/glosarium`, `/tools`, `/video`). Halaman ke-n sebuah daftar lewat `pathHalaman(dasar, n)` (`{path}/halaman/{n}`, halaman 1 tanpa akhiran); slug `halaman` (`SEGMEN_HALAMAN`) dicadangkan untuk semua koleksi.
- SEO selalu lewat `src/modules/seo`: `metadata()` untuk `generateMetadata`, `jsonLd()` + `serialisasiJsonLd()` untuk JSON-LD, `remahRoti()` untuk breadcrumb, `ambilSitus()` untuk pengaturan situs. Jangan menulis `<title>`, canonical, robots, atau JSON-LD manual di halaman. Rute teknis (`/sitemap.xml`, `/sitemap/{jenis}.xml`, `/news-sitemap.xml`, `/robots.txt`, `/feed.xml`) ada di `src/app/(frontend)/` dan hanya merangkai fungsi modul.
- Tag cache di `src/lib/tag.ts` (`TAG`): data halaman publik di-cache dengan tag yang sama dengan yang direvalidasi hook `revalidasiPublik` (`{koleksi}`, `{koleksi}:{id}`, `pilar:{slug}`, `beranda`, `sitemap`, `pengaturan-seo`, `header`, `footer`, `media`, `redirect`, `parameter-tools`, `analitik`, `iklan`, `fitur`, `kode-sematan`). Koleksi publik baru wajib memasang `revalidasiPublik(koleksi)`. Tag `beranda` dibuang global `beranda` dan `newsletter` serta terbitnya artikel, pilar, video, dan tools; koleksi yang baru tampil di beranda ditambahkan ke `DI_BERANDA`. Tag `iklan` dibuang global `iklan` (layout, halaman berslot iklan, beranda, `/ads.txt`).
- Mesin Indexing di `src/modules/indexer`: `kabari(payload, kabar, { req })` memasukkan kabar ke antrean Postgres (koleksi `antrean-indexing`), `jalankanIndexer(payload)` mengirimnya (cron `GET /api/jobs/run` dengan `CRON_SECRET` sesuai jadwal `vercel.json`, sekarang sekali sehari, dan `after()` setelah simpan), log di `log-indexing`, status Google di `status-indeks`. Ketiga koleksi itu hanya ditulis modul indexer dan hanya dibaca admin. Koleksi berhalaman publik baru memasang `kabariMesinPencari(keTarget)` dari `src/hooks/kabariMesinPencari.ts` setelah hook revalidasi (beforeChange, afterChange, afterDelete). Tombol "Cek sekarang" di daftar Status indeks memanggil `POST /api/status-indeks/{id}/cek`: `mintaCekStatus` memeriksa kuota cek harian (`kuotaInspeksi`) dan jeda 10 menit per halaman (`batasCekManual`, klaim atomik lewat kolom `dimintaPada`), memajukan baris `cek-status` ke sekarang (`majukanCek`, tahap dan dasar jadwal tetap), lalu antrean dijalankan lewat `after()`; Google tidak pernah dipanggil langsung dari permintaan admin. Aturan (jendela kirim, jeda ulang, kuota, jadwal cek) sebagai fungsi murni di `aturan.ts` dengan waktu sebagai argumen. Semua panggilan ke Google dan IndexNow lewat adapter (`asli.ts` dengan `fetch` dan JWT akun layanan tanpa pustaka, `palsu.ts` dalam memori), dipilih env `INDEXER_ADAPTER` (`asli` hanya di produksi; dev dan tes memakai palsu; build produksi yang dijalankan tanpa nilai itu ditolak). Tes memakai `adapterPalsu()` + `pakaiAdapterIndexer()` dan opsi `sekarang`. Hapus dan update massal Payload menjalankan hook setiap dokumen secara paralel dalam satu transaksi: `kabari` dengan `req` yang sama berjalan bergiliran, baris antrean baru dibuat lewat `INSERT ... ON CONFLICT DO NOTHING` di sesi transaksi `req` (jangan `payload.create` untuk koleksi dengan kunci unik yang bisa ditulis bersamaan), dan SQL langsung di dalam hook wajib memakai sesi transaksi itu, bukan koneksi pool lain (deadlock). Tes `indexer-bersamaan.int.spec.ts` menjaganya.
- Pantau SEO di `src/modules/pantau` (spesifikasi §8 "Dashboard SEO"): `jalankanPantau(payload)` dipanggil cron yang sama setelah Mesin Indexing dan menjalankan tugas harian yang jatuh tempo (sinkron Search Analytics beserta retensi log indexing 90 hari, dan pindai tautan), lalu memeriksa paling banyak 10 tautan luar yang jatuh tempo per jalan (masing-masing seminggu sekali). Tugas diklaim atomik di `tugas-seo` (cron dobel tidak menjalankan dua kali). Data di koleksi tersembunyi `analitik-halaman`, `analitik-situs`, `tugas-seo`, `temuan-tautan`, dan `tautan-luar`: hanya ditulis modul pantau, dibaca dashboard admin `/admin/seo` lewat `ambilDashboard()` (tautan di grup Ringkasan menu admin lewat `MenuRingkasan`; pilihan periode 7, 28, atau 90 hari lewat `?periode=` dengan perbandingan periode sebelumnya `ringkasSebelumnya`; kisi dashboard paling banyak dua kolom), kecuali `analitik-halaman` yang juga dibaca modul konten (`ambilPopuler`, tag `analitik`) untuk "Paling dicari pekan ini". Search Analytics dan pemeriksa tautan lewat adapter pantau (`asli.ts` memakai token akun layanan dari `indexer/google.ts`, `palsu.ts` dalam memori), dengan saklar `INDEXER_ADAPTER` yang sama; adapter palsu melewati sinkron (data tersimpan tidak tertimpa). Tes memakai `adapterPalsu()` (`dataAnalitik`, `jawabanTautan`), opsi `sekarang`, dan opsi `tugas`. Tanggal Search Analytics adalah tanggal kalender waktu Pasifik (`tanggalPasifik`). Tombol "Pindai ulang sekarang" di bagian Tautan rusak memanggil `POST /api/tugas-seo/pindai`: `mintaPindai` memajukan tugas `tautan` ke sekarang kecuali sedang berjalan atau dimulai kurang dari 10 menit lalu (`batasPindaiManual`, `majukanTugas` satu `UPDATE`), lalu `jalankanPantauSetelahRespons` menjalankannya lewat `after()`; klaim tugas tetap atomik, jadi klik ganda tidak memindai dua kali. Tautan masuk untuk halaman yatim dihitung dari isi Lexical dokumen terbit, relasi pilihan editor, menu header dan footer, dan pilihan beranda; daftar otomatis (rubrik dan halaman berikutnya, terbaru, terkait otomatis) tidak dihitung; tautan ke `/{daftar}/halaman/{n}` dianggap ada bila daftarnya ada (nomornya berubah setiap ada tulisan baru). URL halaman admin lewat `urlAdmin` di `src/lib/admin.ts`.
- Asisten AI di `src/modules/ai` (spesifikasi §10): `jalankan(payload, tugas, masukan, opsi)` satu-satunya pintu ke Claude untuk tugas `brief`, `draf`, dan `meta` (endpoint `POST /api/artikel/asisten`, status di `GET /api/artikel/asisten`, hanya admin dan editor). Di dalamnya: saklar global `asisten-ai`, batas 6 permintaan per menit per pengguna (dihitung dari `log-ai`), harga model dari global, cadangan anggaran atomik di koleksi tersembunyi `pemakaian-ai` (satu baris per bulan waktu Jakarta, `UPDATE ... WHERE terpakai + cadangan <= batas RETURNING` lewat koneksi pool, bukan transaksi `req`), log `log-ai` (tanpa teks masukan dan keluaran, disimpan 13 bulan), lalu pemeriksa jawaban. Prompt, skema JSON (structured outputs: semua properti wajib, `additionalProperties: false`, tanpa batasan panjang), dan pemeriksa per tugas di `prompt/{brief,draf,meta}.ts` sebagai fungsi murni; data database untuk brief di `brief-data.ts` (memakai `artikelLain`, `cariKanibalisasi`, dan `sarankanLink` panel SEO). Prompt dan keluaran mengikuti aturan copy: keluaran model dibersihkan dari em dash dan en dash (`bersihkanTanda`) dan editor diberi tahu jumlahnya. Cek pola tulisan AI (`pola.ts`) dan cek klaim (`klaim.ts`) fungsi murni yang berjalan di browser dari isian form (`blokArtikel`), tanpa API dan tanpa log. Adapter dipilih env `AI_ADAPTER` (`asli` lewat `fetch` ke Messages API dengan `ANTHROPIC_API_KEY`, `palsu` dalam memori; dev dan tes palsu, produksi tanpa nilai itu ditolak dengan pesan), terpisah dari `INDEXER_ADAPTER`. Model per tugas lewat `AI_MODEL_{BRIEF,DRAF,META}` atau `AI_MODEL` (bawaan Sonnet untuk brief dan draf, Haiku untuk meta). Tes memakai `adapterPalsu()` + `pakaiAdapterAi()` dan opsi `sekarang` (bulan lampau supaya baris anggaran milik tes sendiri); E2E memakai pengguna editor baru per tes yang memanggil AI dan menghapus draf buatannya setelah setiap tes (spec lain membaca daftar artikel admin). AI hanya memberi saran: sidebar (`admin/AsistenAi.tsx`) menerapkan isian hanya lewat tombol dengan Batalkan, draf per bagian disalin (bukan disisipkan), dan menerapkan Intinya atau FAQ atau menyalin draf menyalakan `pakaiDrafAi` (setelah tersimpan menyala tidak bisa dimatikan lagi, juga lewat API dan update massal: hook `beforeValidate` `tetapPakaiDrafAi`); artikel itu wajib mencentang checklist `reviewAi` sebelum terbit (validasi field, jadi berlaku juga untuk terbit massal dan terjadwal) dan tombol terbit nonaktif sampai lengkap (`admin/TombolTerbit.tsx`). Sidebar menyebut bahwa teks dikirim ke Claude (Anthropic).
- Iklan dan persetujuan cookie di `src/modules/iklan` (spesifikasi §11): pengaturan dari global `iklan` lewat `muatIklan()` (cache bertag `iklan` dan `halaman`), dan `pilihSlot(pengaturan, posisi, id?)` satu-satunya aturan apakah slot tampil (global menyala, halaman Kebijakan Privasi terbit, AdSense, ID penerbit `ca-pub-` 16 angka, slot aktif, unit angka). Keputusan pemilik: saklar Tampilkan iklan divalidasi `validasiTampilkanIklan` (ditolak selama halaman `SLUG_KEBIJAKAN_PRIVASI` belum terbit, dibaca `kebijakanPrivasiTerbit` dari dokumen utama), dan `iklanSiap` ikut memeriksa `kebijakanTerbit`, jadi banner, skrip awal, pemuat, dan slot berhenti tampil bila halaman itu ditarik dari terbit (karena itu `muatIklan` dan `muatBeranda` juga bertag `halaman`). Label slot "Advertisements" dengan `lang="en"` (keputusan pemilik, pengecualian aturan copy: kebijakan penempatan AdSense hanya mengizinkan "Advertisements" atau "Sponsored links"). Posisi tetap per jenis halaman (`artikel-tengah` setelah paragraf ke-N lewat `sisipkanIklanTengah` dan node Lexical `slotIklan`, `artikel-akhir`, `rubrik`, `tools`, dan `beranda` lewat blok Slot iklan); tidak ada posisi di kotak Intinya, di atas H1, atau di dalam kalkulator. Ukuran tetap (300 x 250, 336 x 280, 320 x 100), jadi `SlotIklan` memesan ruangnya dan iklan tidak menggeser isi (CLS 0); halaman meneruskan `iklan={await muatIklan()}` ke komponennya, beranda lewat `susunBeranda` (`sumber.iklan`). Persetujuan dibaca di browser, bukan di server, supaya halaman tetap ISR: skrip awal di `<head>` (`SkripPersetujuan`, `skripAwal()`) menolak semua sinyal Consent Mode v2 lalu menandai `<html data-persetujuan="belum|perlu|semua">` dari cookie `persetujuan` (versi, pilihan, tanggal; 12 bulan), dan CSS menampilkan banner atau slot dari atribut itu sejak paint pertama. Banner (`PanelPersetujuan`) di atas header, dua pilihan setara; "Hanya yang perlu" berarti tanpa skrip iklan sama sekali; "Pengaturan cookie" di footer membukanya lagi, dan menarik persetujuan menghapus cookie AdSense di domain situs (`KUKI_IKLAN_SITUS`: `__gads`, `__gpi`, `__gpi_optout`, `__eoi`) lalu memuat ulang halaman. `PemuatIklan` (layout) memuat `adsbygoogle.js` hanya setelah "Izinkan semua" dan saat slot hampir terlihat; kode penyedia hanya di `adsense.ts`. Banner, skrip awal, dan pemuat hanya ada bila `iklanSiap`. `/ads.txt` dari global (baris AdSense otomatis dari ID penerbit dan baris tambahan editor), 404 bila tidak ada baris. Tes tidak memanggil Google: E2E memakai `cegatIklan()` (skrip AdSense tiruan yang mencatat `dataLayer` dan mengisi unit) dan ID penerbit tiruan `ca-pub-0000000000000000`; database E2E menerbitkan Kebijakan Privasi lalu menyalakan iklan, jadi semua spec berjalan dengan banner. Spec E2E yang menerbitkan, membatalkan terbit, atau menghapus dokumen publik memicu kiriman IndexNow, dan jendela kirim 5 menit menunda kiriman yang ditunggu `indexing.spec.ts`; spec seperti itu diberi nama yang berjalan setelah `indexing.spec.ts` (contoh `privasi.spec.ts`).
- Ruang redaksi (admin, spesifikasi §23): tema di `src/app/(payload)/custom.scss` (token `--redaksi-*` dengan nilai terang dan gelap, menu kiri selalu gelap, tombol utama biru aksi `#265fe8` karena biru merek `#2f6bff` hanya 4,50:1 dengan teks putih, font Archivo dari `node_modules`). Ikon menu lewat CSS mask di `src/app/(payload)/_ikon-menu.scss` dengan kunci id tautan Payload (`nav-{slug}`, `nav-global-{slug}`): koleksi atau global baru ditambahkan ikonnya di sana. Grup menu yang bisa dilipat juga berikon (`$ikon-grup`, kunci = label grup, id Payload `nav-group-{label}`), jadi grup baru ditambahkan ikonnya di peta itu; isi grup menjorok dengan garis pandu, dan penanda menu aktif di dalam grup menimpa garis itu. Urutan grup menu mengikuti urutan pertama kali grup muncul di `collections` lalu `globals` `payload.config.ts`. Logo dan tanda lewat `admin.components.graphics` (`src/modules/redaksi/admin/Grafik.tsx`, path dari `src/lib/merek.ts`, sumber yang sama dengan `Logo` situs). `MenuRingkasan` (`beforeNavLinks`: logo terbalik, Beranda admin, Dashboard SEO untuk admin, jumlah pesan baru di `#nav-pesan-masuk::after`) dan `KakiMenu` (`afterNavLinks`: Sinkron Google untuk admin, pengguna). Beranda admin `views.dashboard` = `BerandaAdmin` (Payload sudah membungkusnya dengan templat, jadi tanpa `DefaultTemplate`; view kustom di path lain seperti `/admin/seo` tetap membungkus sendiri), data dari `ambilRuangRedaksi(payload, pengguna, { sekarang, periode })` di `src/modules/redaksi` (hanya membaca database; bagian Search Console, status indeks, kesehatan, temuan SEO, dan anggaran AI hanya untuk admin), aturan murni (pekan Senin WIB, perbandingan periode, kalender, perlu perhatian) di `aturan.ts`, grafik SVG tanpa pustaka di `GrafikRedaksi.tsx` mengikuti skill dataviz (satu seri, warna status selalu dengan ikon dan label, tabel tersembunyi untuk pembaca layar). Tata letak beranda admin memakai container query `redaksi` (lebar area isi, bukan layar). Wadah gulir tabel (`overflow-x: auto`) diberi `position: relative`: tanpa itu teks pembaca layar yang absolut (`.redaksi-sr`) di sel tabel diposisikan terhadap bungkus templat Payload dan melebarkan halaman di HP. Jadwal terbit dibaca dari job `schedulePublish` Payload yang belum selesai (`payload-jobs`).
- Fitur pembaca (spesifikasi §23). Global `fitur` (Pengaturan, Fitur; hanya admin) = saklar `formKontak`, `newsletter`, `tombolBagikan`, `daftarIsi`, `waktuBaca`, dibaca halaman lewat `muatFitur()` dan `muatFiturArtikel()` (`src/modules/fitur/cache.ts`, tag `fitur`; `muatFiturArtikel` juga bertag `beranda` karena memuat kotak newsletter akhir artikel). Saklar lama `newsletter.aktif` disembunyikan dan tidak dibaca (disalin ke `fitur.newsletter` oleh migrasi `ruang_redaksi`). Global `kode-sematan` (hanya admin) dibaca layout lewat `muatKodeSematan()` (tag `kode-sematan` dan `halaman`): kode dirender sebagai JSON `#kode-sematan` dan dipasang skrip sebaris `skripSematan()` (tanpa berkas JS); kode jenis `persetujuan` hanya bila Kebijakan Privasi terbit dan baru dipasang setelah `data-persetujuan="semua"` atau peristiwa `persetujuan`. Ada kode `persetujuan` aktif berarti banner persetujuan tampil walau iklan mati, versi pilihan `versiPersetujuan(true)` = 2, `analytics_storage` ikut dibuka, teks banner dari `teksPersetujuan`, dan menarik persetujuan menghapus cookie yang didaftarkan (pola `nama*` untuk awalan).
- Paket konten awal di `src/modules/paket` (spesifikasi §24): artikel paket sebagai data TypeScript di `artikel/` (satu file per artikel, sumber bersama dan subkategori di `bersama.ts`, daftar dan urutan di `paket-awal.ts`), isi berupa markdown terbatas yang diubah ke Lexical oleh `markdownKeLexical()` (fungsi murni; `##`/`###`, daftar, tabel pipa dengan `Tabel: Judul` jadi blok Tabel perbandingan, `> [!info|tips|peringatan] Judul` jadi Callout, `[[tool:id]]`, `[[baca:slug]]`, tautan `/slug` dan `/tools/id` jadi tautan internal; tautan di callout atau tabel ditolak karena blok itu hanya teks). Setiap artikel paket wajib lolos semua butir panel SEO dan aturan copy, dijaga `tests/unit/paket-konten.test.ts`; artikel baru ditambahkan ke `PAKET_AWAL` dan tesnya ikut berjalan. Kartu sampul PNG di `sampul/` dibuat ulang dengan `npx tsx --tsconfig tsconfig.json scripts/buat-sampul-paket.ts` (Playwright dan Archivo yang sudah ada) lalu di-commit; `outputFileTracingIncludes` di `next.config.ts` membawanya ke fungsi `/api/[...slug]`. `imporPaket()` aman diulang (artikel dicari lewat slug termasuk draf dan tidak pernah ditimpa; tools hanya diperbarui bila draf, belum pernah terbit, dan belum disunting; mozaik beranda hanya bila belum ada) dan semua artikel masuk sebagai draf dengan `pakaiDrafAi`. ## Pembaruan untuk pemilik
- Setiap pembaruan yang dikirim ke pemilik punya versi `vX.Y.Z` (Z perbaikan, Y fitur, X perubahan besar). Naikkan dengan `npm version X.Y.Z --no-git-tag-version` (`package.json` dan `package-lock.json`), tambah entri di `CHANGELOG.md` (bahasa Indonesia, untuk pemilik), commit, lalu setelah CI hijau buat tag beranotasi `vX.Y.Z` di `master` dan push tag-nya.
- Zip pembaruan bernama `point-lat-vX.Y.Z.zip`: clone bersih `master` berisi tag (folder `point-lat`, dengan `.git`, `origin` GitHub, tanpa `.env`). Perintah pasang untuk pemilik (Mac, npm, tanpa Docker): `cd "$HOME/Documents/Virgiawan/website done"`, `rm -rf point-lat-lama`, `mv point-lat point-lat-lama`, `unzip -q "$(ls -t ~/Downloads/point-lat*.zip | head -1)"`, `cp point-lat-lama/.env point-lat/.env`, `cd point-lat`, `npm ci`, `git describe --tags`, lalu `git push origin master` (Vercel merilis otomatis; build Vercel menjalankan migrasi produksi) dan setelah CI hijau `git push origin vX.Y.Z`. Bila pembaruan membawa migrasi dan pemilik memakai pratinjau lokal: `npm run migrate` (ke proyek Supabase pratinjau di `.env`). Setiap kiriman menyertakan blok perintah ini lengkap dengan versinya, ditambah langkah sekali jalan bila ada. Blok perintah untuk pemilik tanpa komentar `#` di baris perintah: zsh di macOS meneruskan `#` dan kata sesudahnya sebagai argumen (push v1.1.0 gagal karena itu); penjelasan ditulis di luar blok.
- Sesi Claude yang hanya punya akses baca ke GitHub tidak push: commit dan tag dibuat di repo sesi, ikut di zip, dan pemilik yang mendorongnya.

## Batasan
- Jangan commit `.env`. `.env.test` boleh di-commit karena hanya untuk database tes lokal dan tidak boleh berisi `CLOUDINARY_*`, `GOOGLE_SERVICE_ACCOUNT_JSON`, `CRON_SECRET`, `INDEXER_ADAPTER=asli`, `ANTHROPIC_API_KEY`, atau `AI_ADAPTER=asli`. Kredensial Google dan kunci API Claude hanya di env server Vercel, tidak pernah di CMS, log, atau tes.
- Tanya dulu sebelum menambah dependensi baru di luar rencana.
- Database Supabase (produksi dan pratinjau) hanya diubah lewat migrasi dan build Vercel. Connection string Supabase hanya di env Vercel, secret GitHub Actions, atau shell pemilik untuk satu perintah, tidak pernah di file yang di-commit. Secret GitHub Actions hanya `BACKUP_DATABASE_URL` (role baca saja) dan `BACKUP_KUNCI_PUBLIK`.
- Jalankan `npm run generate:types` lalu `npm run typecheck` setelah mengubah koleksi atau global.
- Jalankan `npm test` sebelum commit, dan `npm run test:e2e` bila halaman publik berubah.
- `npm run build` membaca database dev untuk halaman statis (layout, `/`, `/glosarium`, `/tools`, `/video`, 404). Setelah skema berubah, jalankan `npm run seed` dulu supaya kolom baru terdorong ke database dev.
